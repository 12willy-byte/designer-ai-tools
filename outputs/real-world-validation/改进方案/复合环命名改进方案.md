# 复合环命名改进方案（草案 v1）

> 状态：施工蓝图，未实施。基线 commit `b71cf52`。
> 关联差距：露露姨 22.82㎡ 客厅复合环无法命名（"客厅"文字距环 >2.5m）；罗菁 63.14㎡ 复合环环内占用命名正常。

## 1. 问题

现行命名两级机制（`core/pdf_plan_reader.py`）：

1. `_relabel_rooms_by_inner_texts`（L1420）：文字中心落在环内 → 环内占用命名（高置信）；
2. `_disambiguate_room_names`（L1453）：环外 2500mm 兜底，只取未占用文字，标 `name_source=nearest_outside` + `name_confidence=low`。

露露姨图纸中"客厅"文字写在 22.82㎡ 复合环外约 3m 的空白区（图面拥挤，厅名被挤到餐厅/过道一侧），超 2500mm 阈值 → 环保持"未命名空间"。结果是全屋面积最大的空间无名，下游概念/布局/预算分房间小计全部失真。

## 2. 根因诊断：设计师为什么把房间名写在环外/远处

对两套真实图纸与常见制图习惯的归纳：

- **图面拥挤外溢**：小房间/复合空间内部被家具、尺寸标注占满，房间名写到邻近空白区（本案例即此类）；
- **引线标注**：文字旁画细指引线指向目标区域（工装图、深化图常见，家装布置图较少）；
- **成组命名**：一个名字服务一个复合区（"客餐厅"写在餐厅侧，指整个厅）；
- **竖排/旋转文字**：沿墙竖排书写，文字盒中心可能落在环外但文字体贴着环边界；
- **编号+图例**：房间只标编号（R1/R2），真名在图纸角落图例表里（本次未遇到，但客观存在）。

共性：**"文字中心点距环心的直线距离"不是设计师表达归属的真实通道**，归属表达依靠空白区邻近、引线、共边贴放等空间关系。单一距离阈值（2500mm）是对这些关系的过度简化。

## 3. 候选方案对比

| 方案 | 原理 | 可行性 | 误伤风险 | 成本 |
|---|---|---|---|---|
| a. 引线/指引线识别 | 文字旁短细线（非墙、非标注）端点落入某环 → 建立归属 | 中：需从 single_segs 里区分指引线与家具线/尺寸线，特征（一端贴文字盒、另一端入环、长度 200–1500mm、无配对）可判，但指引线在家装布置图出现率低，本图纸就没有 | 低：指引线形态特异 | 高（新几何识别器） |
| b. 文字-环亲和度评分 | 距离 + 文字字号 + 语义词表（客厅/主卧等强房间词 vs 数字/材料标注）+ 中间是否隔墙体，综合打分替代单一阈值 | 高：全部输入现有（words 有字号、rooms 有环、walls 可判遮挡）；阈值变评分，可调 | 中：打分放宽后，"次卧贴名到条带"类错配可能复发，需墙体遮挡项压住 | 中 |
| c. 分区反推+全局匹配 | 已知环集合与未占用房间名集合做二分图匹配（匈牙利算法），代价矩阵=距离+语义，全局最优而非贪心就近 | 中高：解决"一个名字被近处假环抢走"的全局一致性；但需先验"应有几个房间名"，图缺名时无解 | 中：全局最优可能把远名硬配给大环（本案例反而是想要的行为），需设匹配代价上限 | 中高 |
| d. 用户确认通道 | 对"面积 ≥10㎡ 且无名"的环，向 `questions_to_confirm.json` 写入"22.82㎡ 空间疑似客厅？（最近未占用文字：客厅，距 3.0m）"待确认项 | 极高：机制现成（`build_space_questions`，space_profile.py:69），只需加一条规则 | 零：不改命名结果，只增加提示 | 低 |

## 4. 推荐方案：b + d 组合，分两步走

**第一步（必做，低成本闭环）：方案 d**——先保证"无名大环一定浮出水面让人知道"。

**第二步（核心改进）：方案 b**——亲和度评分替代距离阈值，把"客厅写在 3m 外空白区"这类最常见外溢纳入自动命名，仍保持低置信标注。

不选 a 的原因：本图纸无指引线，投入产出比低，且几何识别器误检会引入新噪声；不选 c 的原因：全局匹配在"图缺名/多名"时不稳定，且匈牙利算法引入新依赖，与项目零依赖纯启发式风格不符。c 可作为 b 落地后的第三步演进（见 §7 不做清单外的远期项）。

### 方案 b 评分模型（建议）

```
score(text, room) = w1·语义分 + w2·(1 − dist/max_dist) + w3·字号分 − w4·遮挡惩罚
```

- **语义分**：内置房间名词表（客厅/餐厅/主卧/次卧/厨房/卫生间/阳台/书房/玄关/走廊及同义词），命中=1.0，数字/材料词=0；
- **距离分**：dist 为文字盒中心到环边界（非环心）的最近距离，max_dist 放宽至 5000mm；到环边界距离优于到环心，天然优待贴边外放的长条形环；
- **字号分**：文字高度 ≥ 同图房间名中位字号 → 1，否则线性衰减（标注数字通常字号小）；
- **遮挡惩罚**：文字与环边界最近点连线穿过 ≥2 道墙体中心线 → 惩罚 0.5（防止隔壁房间名穿墙贴名）；
- **采纳门槛**：score ≥ 0.6 且为全场最高分 → 命名，`name_source="affinity_outside"`，`name_confidence="low"`，evidence 记录各分项得分；< 0.6 不命名，转入方案 d 提问。

**置信度标注纪律**：凡环外命名一律 `low`；环内占用维持现状；评分 evidence 必须落 JSON（可回溯，沿袭 wide_arc_downgrade 留痕风格）。

**误伤防护**：①旧 2500mm 路径优先，评分路径只处理旧路径放弃的环 → 罗菁行为不变；②遮挡惩罚压住穿墙贴名；③词表外文字永不参与评分命名；④评分命名与最近邻命名互斥，一个环至多一条命名路径。

## 6. 验收标准

1. 露露姨：22.82㎡ 环命名为"客厅"（`name_source=affinity_outside`，low），或至少在 `questions_to_confirm.json` 出现对应待确认项——两者必居其一，不允许再静默无名；
2. 罗菁基线逐项零漂移：比例 7.20777 / 9 房 / 融合 10 房 / 门 13（6+7）/ 窗 10 / 6.08㎡ 环仍"未命名空间3"（评分路径不得把它改名，词表分+遮挡惩罚应压住）；
3. 次卧 2.73㎡ 条带环不因评分路径获得新名字（仍低置信兜底或无名）；
4. **13 个验收脚本全绿**（12 个既有 + 泛化脚本更新断言后）。

## 7. 风险与不做清单

**风险**：
- 评分权重（w1–w4）是新调参面——纪律：权重只许在词表/距离/字号/遮挡四项内调，禁止按图纸特判；
- 词表覆盖率决定语义分上限，生僻叫法（"起居室""饭厅"）首期可能漏 → 词表留 TODO，漏了走方案 d 提问兜底，不阻塞；
- 距离基准从环心改环边界会影响旧 2500mm 路径的可比性 → 旧路径保持环心口径不变，只在评分路径用环边界。

**不做清单**（防止范围蔓延）：
- 不做引线/指引线几何识别器（方案 a 整体排除）；
- 不做匈牙利全局匹配（方案 c 排除，远期再议）；
- 不改环内占用命名逻辑、不动 `_relabel_rooms_by_inner_texts`；
- 不做编号+图例表的跨区解析；
- 不调 2500mm 阈值本身、不改已有 `nearest_outside` 标注语义；
- 不引入新 Python 依赖；
- 不动布局/预算/闸门模块。

## 实施回注（已落地，验收全绿）

按 b+d 路线实施完成。双图实测后对方案参数做两处收紧（均有实测数据依据，
详见泛化报告 §8）：

1. **遮挡惩罚阈值由 ≥2 道墙收紧为 ≥1**：罗菁平面图"主卧"@4.2m 仅穿 1 道墙
   （0.748），≥2 漏挡会造成基线漂移；正确候选实测均为 0 穿墙；
2. **语义分增加类型-面积物理先验**（阳台≤10㎡、厨卫≤12-15㎡、玄关走廊储物
   ≤8㎡）：22.82㎡ 环被贴邻 1.24m/0 穿墙的"阳台"文字以 0.925 满分误采纳，
   距离/字号/遮挡四项无法区分"近但名实不符"，物理先验是唯一能干净区分的
   证据（沿袭门宽/净宽物理先验风格，普适非特判）；
3. 提问线索取**语义有效最高分候选**，保证问题问"疑似客厅？"而非"疑似阳台？"。

落地结果：双图亲和路径零采纳（安全的保守态），露露姨 22.82㎡ 环转提问通道
（"22.82㎡ 空间疑似客厅？"入 questions_to_confirm.json 并随真实模式 e2e 进
交付包），罗菁逐项零漂移，12 脚本全绿。泛化脚本已固化防漂移断言。
