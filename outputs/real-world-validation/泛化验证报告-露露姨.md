## 5. 诚实结论：离"即插即用"还差什么

**能做到的（开箱即用部分）**：比例校准（双图验证零漂移）、竖排反读投票、双图融合框架、
诚实化机制（limitations/虚拟边界/闸门拦截/不伪造产物）在新图纸上全部复现，系统**能跑、不崩、不撒谎**。

**做不到的**：对"含家具线条的单张布置图"——最常见的真实输入——房间清单半数名实不符、
客厅/卫生间消失、门计数膨胀 4–5 倍、布局草案被窗户缺口拦截。用户拿到的概念/预算产物
建立在残缺空间事实上，必须人工复核后才能用。

**结论：这套系统对新图纸是"可安全试运行（fail-safe）"，远未到"即插即用"。**
打通最后一段需要的不是调阈值，而是四个结构性改进：家具线过滤、命名环内优先、
门宽物理先验降级、窗户缺失时的布局降级模式（如"仅家具摆放建议"而非整体拦截）。

## 7. 改进后复测（四项普适改进）

按差距清单落地的四项结构性改进（均为普适规则、零图纸特判、罗菁基线锁定后实施）：

1. **家具线条过滤**（`core/pdf_plan_reader.py`）：未配对单线做传递闭包分级——与墙线网连通的判
   structural（仍参与成环），孤岛判 floating（留痕 `furniture_lines`，闭环级过滤：
   净宽 <1m 物理下限剔除；面积 <3㎡ 且浮动单线覆盖 ≥50% 剔除；剔除留痕 `removed_rooms`）。
   实测真走廊覆盖率 0.30–0.36 与 1m 假条带 0.21 在 1.0–1.5m 区间无法干净区分，故该区间
   不做覆盖率剔除（已写入代码注释）。曾试"floating 排除出成环"导致罗菁房间塌缩，回退为
   "标记+闭环级过滤"。
2. **命名环内优先**：环内文字"占用"命名权；环外兜底只取未占用文字，且标
   `name_source=nearest_outside` + `name_confidence=low`。
3. **门宽物理先验**（`_DOOR_LEAF_MAX_MM=1200`）：弧线佐证但宽 >1.2m 的"门"降级为
   opening(0.4) 并留痕 `wide_arc_downgrade`；洞口侧翼规则同步收紧（两缘均非中线单线的
   gap 需门扇/窗佐证）。
4. **无窗降级模式**（`core/automation_gate.py` + `core/layout_draft.py`）：缺窗从
   `layout_missing`（硬拦截）移入新增 `layout_degraded`（降级），`layout_draft` 以
   `layout_mode="draft_degraded"` 生成"仅家具摆放讨论稿"，摘要含醒目 banner 声明
   "采光面未知……需人工补充"；缺门洞/结构/机电仍硬拦截。
   **联动修复**：`core/budget_estimate.py` 新增 `_counts_as_interior_door`（door→计；
   opening ≤1.2m→计；超宽/unverified→不计），堵住"门计数膨胀→预算放大"通道。

### 评分模型最终参数（与方案草案的两处偏离，均有实测依据）

```
score = 0.45·语义 + 0.30·(1 − dist_mm/5000) + 0.25·字号 − 0.4·(穿墙 ≥1)
采纳：score ≥ 0.6 且为全场最高；仅处理旧 2500mm 就近路径放弃的环
```

- 语义分 = 房间名词表命中 **且通过类型-面积物理先验**（阳台≤10㎡/厨卫≤12-15㎡/
  玄关走廊储物≤8㎡；客厅餐厅卧室等无上限先验）。**偏离 1**：草案语义分仅词表命中；
  实测"阳台"文字贴邻 22.82㎡ 环（1.24m、0 穿墙、0.925 满分）会被误采纳为该环之名，
  距离/字号/遮挡四项均无法区分"近但名实不符"，物理先验（沿袭门宽 1.2m/净宽 1m
  既有风格，普适非特判）是唯一干净证据。
- 遮挡惩罚阈值 **≥1 道墙**（草案为 ≥2）。**偏离 2**：实测罗菁平面图"主卧"@4.2m
  仅穿 1 道墙（0.748），≥2 漏挡会造成基线改名漂移；正确候选（贴邻环空白区文字）
  均为 0 穿墙，≥1 正好分开两类。
- 提问线索取**语义有效最高分候选**（而非被先验/遮挡压掉的最高分），
  保证问题问"疑似客厅？"而非"疑似阳台？"。
